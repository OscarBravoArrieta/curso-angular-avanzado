10. Reactividad en Angular: Migración a Input Signals
https://platzi.com/cursos/angular-avanzado/implementa-input-signal-para-componentes-reactivos/

     Los inputs Signals en Angular son una API moderna basada eb funciones, que reemplaza al decorador clásico @Input.
     Los input signals, fueron introducidos en Angular, para cambiar la forma en que los componentes reciben datos, estos trasnforman los datos
     de entrada en señales reactivas de solo lectura, por tano se optimiza sustancialmente la detección de cambios, haciéndola más precisa y eficiente.

     Para utilizarlos, debes importar la función input desde @angular/core.

     A diferencia de los decoradores tradicionales, el valor se lee ejecutando la propiedad como una función (ej. miPropiedad())

     ngOnChanges() Se puede utilizar para leer loc cambios de un input dignal, sin embargo, lo ideal para la nueva reactividad de angular, es a través de effect:

     doubleDurationA = signal(0);
     doubleDurationB = computed(() => this.duration() * 2);


     constructor() {
        effect(() => {
           const duration = this.duration()
        })

        effect(() => {
            this.duration()
            this.doubleDUrationA.set(this.duration() * 2 )
        })
     }

     Otro aspecto a tener en cuenta, es que ngOnChange(), es un solo método para leer todos los valores, por lo que toca buscar el valor a leer, dentro de un objeto, mientas que con effect
     se puede hacer uno a uno, es decir, de forma granular.

     Los Input Signals transforman la forma en que Angular detecta los cambios, pasando de una revisión general a una reactividad granular. 
     Imagina que en lugar de revisar toda tu casa para ver si dejaste una ventana abierta, tuvieras un sensor que te avisa exactamente cuál ventana se abrió. 
     Esto mejora drásticamente el rendimiento de tu aplicación, especialmente en proyectos pesados como dashboards o aplicaciones con Server-Side Rendering (SSR). 
     Al dejar atrás el decorador @Input(), adoptas un enfoque mucho más declarativo. Angular ya no tiene que adivinar qué componente necesita actualizarse; 
     el Signal le avisa directamente. 
     Esto se traduce en interfaces más rápidas, menor consumo de memoria y una experiencia de usuario mucho más fluida sin importar el tamaño de tu proyecto.

13. linkedSignal en Angular: computed con set
https://platzi.com/cursos/angular-avanzado/linkedsignal-en-angular-computed-con-set/

 Angular ha estado creando ciertas primitivas fundacionales:

 1. Signals: Para declarar un signal de forma explícita y declarativa desde cero.
 2. computed: Permite declarar un nuevo signal a partir y dependiendo de otro.
 3. effect: Lee los cambios de un signal y basado en ello, podemos ejecutar funciones 

 linkedSignal: 
 
 Entre otras cosas, viene a contrarrestar algunas reglas no escrita en el mundo de Angular,
 Cómo es el caso evitar el uso de effect

 cover = signal('')

 if(product.images.length > 0) {
    this.cover.set(product.images[0])
 }

 Para convertirlo a computed:

 cover = computed(() => {
    return this.product()?.images[0] ?? ''
 })
 
 De esta fomrma es más declarativo, sabemos que cover se calcula a partir de producto
 Cada vez que producto sufra cambios, se vuele a recalcular cover.

 DESVENTAJA DEL computed: no se le puede hacer un set, la unica forma de que cover cambie es que producto cambie.
 En fin, los computed no se pueden modificar.

 Estas desventajas, se pueden resolver con la directiva linkedSignal, la cual es igual a un computed, pero si deja hacer set:

 cover = linkedSignal(() => {
    const product = this.product()
    if(product && product.images.length > 0) {
        return product.images[0]
    }
 })

 Con linkedSignal, puedo tener las bodades del computed y adempas poder modificarlo 

 otra forma de usar linkedSignal, es haciendo uso del proviousVv
 $cover = linkedSigal({
    source: this.$product,
    computation: (value, previusValue) => {
        if(product && product.images.length > 0) {
            return product.images[0]
        }
        return previousValue?.value
    }
 })
